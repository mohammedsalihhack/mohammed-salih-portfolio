REVERSE ENGINEERING

XOR — Ghidra Reverse Engineering

#01

Challenge Information

Challenge: XOR

Category: Reverse Engineering

Tool: Ghidra

Objective: Analyze the ELF binary, identify the password transformation and recover the hidden flag.

1. Open the Binary in Ghidra

Open the binary named xor in Ghidra. 

File
↓
Import File
↓
Select xor
↓
Analyze

Wait until Ghidra completes the automatic analysis.

2. Find the main Function

Navigate through: 

Symbol Tree
↓
Functions
↓
main

The decompiler shows the main program logic. The program asks the user for a password: 

printf("Enter a Password: ");

3. Identify the Encryption Function

Inside main(), the user input is passed to: 

encrypt(local_78, __edflag);

The important operation inside encrypt() is: 

__block[local_1c] =
    __block[local_1c] + -10;

This means that every character is shifted backwards by 10 ASCII positions. 

Encrypted = Original - 10

4. Find the Encrypted Password

The binary contains the following transformed password: 

9J<q=^':h*#*d:#+Jh*9)#'+#>)'Bs

The program compares the transformed user input against this stored string.

5. Reverse the Transformation

The encryption operation is: 

Encrypted = Original - 10

Therefore, the reverse operation is: 

Original = Encrypted + 10

Example: 

9 → ASCII 57
57 + 10 = 67
67 → C

J → ASCII 74
74 + 10 = 84
84 → T

< → ASCII 60
60 + 10 = 70
70 → F

Therefore: 

9J< → CTF

6. Decode Using Python

enc = "9J<q=^':h*#*d:#+Jh*9)#'+#>)'Bs"

flag = ""

for c in enc:
    flag += chr(ord(c) + 10)

print(flag)

Output: 

CTF{Gh1Dr4-4nD-5Tr4C3-15-H31L}
FLAG RECOVERED CTF{Gh1Dr4-4nD-5Tr4C3-15-H31L}

DIGITAL FORENSICS

x-tension — File Forensics

#02

Challenge Information

Challenge: x-tension

Category: Digital Forensics / File Analysis

Objective: Identify the true format of a suspicious file disguised as a PDF and recover the hidden flag.

1. Initial File Analysis

The provided file was named: 

confidential.pdf

Instead of trusting the extension, the file was examined using: 

file confidential.pdf

Result: 

confidential.pdf: shell archive text

The file was not actually a PDF. It was a Shell Archive (SHAR).

2. Extract the SHAR Archive

unshar confidential.pdf

This produced: 

archive.ar

3. Analyze the AR Archive

file archive.ar
ar t archive.ar
ar x archive.ar

The archive contained: 

archive.cpio

4. Extract the CPIO Archive

cpio -idmv < archive.cpio

The extracted file was: 

flag.gz.bz2

5. Recursive Decompression

Each layer was identified using the file command before applying the appropriate decompression utility.

01 BZIP2 — bunzip2
02 GZIP — gunzip
03 LZIP — lzip -d
04 LZ4 — lz4 -d
05 LZMA — xz --format=lzma --decompress
06 LZOP — lzop -dc
07 XZ — xz -dc
08 ASCII / HEX — xxd

6. Final Hexadecimal Data

The final output contained: 

4354467b7033346b5f347263683176335f7033726630726d346e63337d

The hexadecimal data was decoded using: 

echo "4354467b7033346b5f347263683176335f7033726630726d346e63337d" | xxd -r -p
FLAG RECOVERED CTF{p34k_4rch1v3_p3rf0rm4nc3}

Key Learnings

  • File extensions should never be blindly trusted during forensic analysis.
  • The file command helps identify the actual file format.
  • Nested archives require systematic extraction and verification.
  • Every extraction layer should be checked before continuing.
  • Hexadecimal data can be another final encoding layer.
